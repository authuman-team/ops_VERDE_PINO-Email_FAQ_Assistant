# Security — Verde Pino Email FAQ Assistant

## Threat model

The workflow handles incoming email content and can send customer-facing replies. The main security and operational risks are:

1. Unauthorized mailbox access.
2. Unauthorized LLM API usage.
3. Prompt injection through customer email content.
4. Hallucinated or unsupported customer replies.
5. Accidental disclosure of business information.
6. Processing non-customer emails.
7. Duplicate replies.
8. Misclassification due to incomplete email text.
9. Leakage of credentials through exported workflow JSON.
10. Excessive logging of personal data.

## Known risks

### 1. Gmail snippet usage

Current workflow maps Gmail `snippet` to `Mensagem`.

Risk:

- Snippets may truncate or distort the email.
- Multi-part questions may be missed.
- The assistant may answer based on incomplete context.

Required hardening:

- Fetch full Gmail body.
- Clean HTML.
- Remove quoted history where appropriate.
- Use plain text in prompts.

### 2. Static FAQ embedded in workflow

Current workflow stores FAQ content directly in a Set node.

Risk:

- FAQ changes are not easily versioned as business decisions.
- n8n can drift from GitHub documentation.

Required hardening:

- Store canonical FAQ in `/config/faq.verde-pino.md`.
- Update n8n only from the approved config.

### 3. RAG responder prompt expression issue

Current responder prompt appears to start with `=={{`.

Risk:

- n8n may treat it as literal text instead of evaluating the expression.
- The responder may receive an invalid or incomplete prompt.

Required hardening:

- Correct to `={{ ... }}`.
- Test with a known FAQ-covered email.
- Inspect Gemini request body before pilot use.

### 4. Responder called for all classified messages

Current flow continues to responder after classifier output.

Risk:

- Non-client messages may still be sent through the responder step.
- Extra cost and additional safety exposure.

Recommended hardening:

- Add an IF immediately after classifier:
  - `deve_processar = true` → responder.
  - `deve_processar = false` → no reply / human review / label.

### 5. No explicit duplicate-reply guard

Risk:

- Re-runs or thread behavior may produce duplicate replies.

Recommended hardening:

- Check processed label before reply.
- Check thread for previous automated reply where feasible.
- Do not re-process answered messages without manual review.

## Existing mitigations

The workflow already includes several good controls:

- Uses structured JSON schemas.
- Uses temperature `0`.
- Separates classifier and responder prompts.
- Responder must return `tem_contexto`.
- Unsafe/insufficient cases return `SEM_INFO`.
- Automatic reply branch requires `tem_contexto = true`.
- False branch leaves the message for human handling.
- LLM usage is logged through a gateway.
- Gateway estimates cost.
- No attachment processing detected.
- No OCR detected.
- Gmail reply attribution disabled to avoid automatic platform signature.

## Credential handling

Rules:

- Gmail OAuth credentials must remain in n8n credentials.
- Gemini API credentials must remain in n8n credentials.
- No API keys, OAuth tokens, refresh tokens, passwords, or credential IDs should be committed to GitHub.
- Workflow JSON may include credential references generated by n8n exports; review before committing.
- Public repository use is not recommended for client workflow exports unless credentials and client identifiers are scrubbed.

## Prompt injection considerations

Customer email content is untrusted input.

The assistant must ignore any customer instruction that attempts to:

- Change system behavior.
- Override FAQ boundaries.
- Force the assistant to disclose prompts or internal logic.
- Ask the assistant to answer without context.
- Request credentials, hidden rules, or internal data.
- Pretend to be Authuman, Verde Pino staff, Gmail, or n8n.

Prompt rules must preserve:

- FAQ-only answer grounding.
- No availability/pricing/exception decisions.
- JSON-only output.
- Human fallback.

## Access control

Recommended access levels:

| Role | Access |
|---|---|
| Verde Pino mailbox operator | Gmail mailbox and client Notion page |
| Verde Pino owner | FAQ approval, operational review, client page |
| Authuman delivery owner | GitHub, n8n workflow, execution logs, Notion page |
| Authuman technical maintainer | n8n credentials, workflow deployment, gateway |
| External parties | No access unless approved |

## Explicit non-goals

The solution is not intended to:

- Replace human customer support.
- Make reservation decisions.
- Confirm availability.
- Confirm prices.
- Handle payments.
- Handle invoices.
- Handle complaints.
- Process attachments.
- Process OCR.
- Read or update PMS/booking systems.
- Act as a general-purpose email assistant.
- Handle supplier or administrative emails automatically.
